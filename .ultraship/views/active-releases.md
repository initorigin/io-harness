# Active releases

## io-harness 0.45.0

**Execution state:** DEVELOPING
**Release fit:** probable
**Target mode:** published
**Outcome:** Give the agent its own voice, and let it read the boundary it is working inside instead of discovering it by being refused.
**Today the system prompt is three sentences the embedder cannot see.** `system_prompt` (`src/run.rs:11143`), `WORKSPACE_PROMPT` (`src/run.rs:11190`) and `TREE_PROMPT` (`src/run.rs:11326`) are private `const`s behind private `fn`s. They name four tools and say to work in small steps. A program built on this crate that wants its agent to introduce itself, to follow a house style, or to know what product it is working on has exactly one way to say so today — `TaskContract::constraints`, which is a list of rules the goal is checked against and reaches the model in the *user* turn, re-sent whole on every step. The thing an embedder actually wants to set is the one string the crate keeps to itself.
**And the prompt describes a world with no edges.** A run under a real policy is refused at `dispatch` — `Policy::check` (`src/policy.rs:626`) returns `Effect::Deny` and the model gets a refusal observation naming the rule. That refusal is correct, it is attributable, and it costs a completion, a tool call and a step, every single time, for a fact the crate knew before the request was built. `Policy::default()` denies reads and writes of `.env`, `*.pem`, `id_rsa`, `id_ed25519` and `*.key` (`src/policy.rs:287`), asks about every write, asks about every exec and denies all egress — four tiers and five patterns the agent is never told about. The same is true of containment: with `TaskContract::exec_sandbox` set, every command is wrapped by whatever `sandbox::select` (`src/sandbox.rs:551`) chose on this host, and on a stock Ubuntu 24.04 that is `PortableFloor` — resource caps and **no** filesystem or egress confinement (0.40.0). The agent is told none of it, so it cannot plan around it and cannot report it.
**So the system block gains a boundary section, and the prompt gains three composition states.** The boundary section is rendered from the very `Policy` the run enforces and, when containment is on, from the backend `select` actually returned — including a degraded floor, named as degraded. `TaskContract::prompt: SystemPrompt` is `Builtin` (today's prompt, and the default, unchanged byte for byte), `Append(String)` (the caller's text after the crate's description of the agent and its tools, before the crate's own rules), or `Replace(String)` (the caller's description instead of the crate's). A run whose policy enforces nothing and whose prompt is `Builtin` sends the bytes 0.44.0 sent, which is the negative control this release is checked against.
**What a repository says about itself stops being a constraint and stops being invisible.** `read_instructions` (`src/config.rs:1681`) already defaults to `AGENTS.md` (`src/config.rs:158`) — but only when an `[instructions]` table is present, so the repository that carries the file every other agent reads and no `io.toml` at all is read by none of it. `Config::discover` now looks by default, an empty `files` list is how a project says no, and what it finds lands in a delimited section of the system block instead of being pushed into `TaskContract::constraints` (`src/config.rs:1437`). Guidance reads as guidance; a constraint stays the thing the goal is checked against. **It is also untrusted text moving to a more authoritative position, and this release treats that as a property to be bounded rather than a detail** — the section is delimited, framed to the model as the repository's own guidance rather than the operator's instruction, and emitted *before* the boundary section and before the crate's turn-ending rule, both of which it therefore cannot displace.
**The prompt is also shaped for the family answering it.** The crate reaches four wire shapes and, through `Compatible`, roughly two dozen vendors, and each family documents a different convention for how a long system block should be delimited. `PromptFamily` is derived — from the provider directly for the two built-ins, from the configured model slug for `OpenRouter` and `Compatible`, and `Generic` for anything unrecognised. **Only the delimiters differ.** Every family gets the same sections, in the same order, ending with the same sentence, and that is asserted by stripping the delimiters and comparing the rest byte for byte — because a per-family prompt that drops a rule for one vendor is a crate that behaves differently depending on who answered, and no amount of prose about tone is worth that.
